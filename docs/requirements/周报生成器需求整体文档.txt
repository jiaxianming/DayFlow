  设计 · 第 2 节：多智能体协作详细设计（核心）

  四个 Agent 的规格

  每个 Agent = 一个独立配置的 ChatClient（专属 system prompt +
  角色），通过结构化对象传递数据，而非自由文本。

  1. Planner（主编 · 规划）

  - 输入：日期范围、当天数据量预估、报告类型（日报/周报）
  - 输出：ReportPlan（结构化）—— 板块清单
  - 职责：决定报告分几个板块、每块用什么数据源、重点是什么
  - 结构化输出：

  /** 报告规划（主编产出） */
  interface IReportPlan {
    title: string            // 例："2026-07-07 工作与学习日报"
    sections: [{
      name: string           // 例："今日工作进展"
      dataSource: string     // ACTIVITY | NOTE | TASK
      focus: string          // 该板块要突出的重点
    }]
  }

  2. Collector（采集记者 · Tool Calling）

  - 输入：ReportPlan + 日期范围
  - 输出：CollectedMaterial（结构化素材包）
  - 职责：根据 Planner 指派的板块，调用工具去拉数据，去重归类
  - 关键：通过 Spring AI Tool Calling 调用业务 Service（这是展示"Agent
  调外部工具"的核心）

  @Component
  class ReportDataTools {
      @Tool(description = "查询指定日期范围内的用户工作活动记录")
      fun listActivities(startDate, endDate): List<Activity> { ... }

      @Tool(description = "基于关键词检索相关学习笔记片段")
      fun searchNotes(query, dateRange): List<NoteChunk> { ... }  // RAG

      @Tool(description = "查询指定日期范围内完成的任务")
      fun listCompletedTasks(start, end): List<Task> { ... }
  }
  Collector 把工具返回结果归纳成 CollectedMaterial。

  3. Writer（撰稿编辑 · 撰写）

  - 输入：ReportPlan + CollectedMaterial
  - 输出：DraftReport（草稿，分板块内容）
  - 职责：把素材写成通顺、有重点、不啰嗦的中文段落，严格按 Planner 的板块结构

  4. Reviewer（审校 · 质检 + 反馈循环）

  - 输入：DraftReport + 原始 CollectedMaterial
  - 输出：ReviewResult

  interface IReviewResult {
    passed: boolean          // 是否通过
    issues: [{section, type, description}]  // 问题清单
    suggestions: string      // 给 Writer 的修改建议（若未通过）
  }
  - 职责：查夸大失真（写的内容在素材里没有依据）、重复啰嗦、板块缺失、语气不当。

  编排流程（编排层 = ReportOrchestrationService）

  mermaid
  flowchart TD
      Start([触发: 日报/周报]) --> Planner[Planner 规划板块]
      Planner -->|ReportPlan| Collector[Collector 采集素材]
      Collector -->|调用 Tools| Tools[(Activity/Note/Task)]
      Tools -->|原始数据| Collector
      Collector -->|CollectedMaterial| Writer[Writer 撰写草稿]
      Writer -->|DraftReport| Reviewer{Reviewer 审校}
      Reviewer -->|passed=true| Done([完成, 落库])
      Reviewer -->|passed=false & retry<2| Writer
      Reviewer -.->|带 suggestions| Writer
      style Reviewer fill:#fff3cd
      style Done fill:#d4edda

  反馈循环机制（"多智能体"的灵魂）

  retryCount = 0
  loop:
    draft = Writer.write(plan, material, prevReview?)   // 首轮无 prevReview
    review = Reviewer.review(draft, material)
    if review.passed or retryCount >= MAX_RETRY(2):
        落库 → 返回
    else:
        retryCount++
        带 review.suggestions 重新进入 Writer

  这是和"单纯多步串联"的根本区别：Reviewer 会真实地打回 Writer
  的稿子，让它基于素材重写，最多重试 2 次后强制通过（防止死循环 + 控成本）。

  │ 入      │                  │ ）                                        │
  └─────────┴──────────────────┴───────────────────────────────────────────┘

  Spring AI 实现要点汇总

  - ChatClient 多实例：plannerChatClient / writerChatClient / ... 各自
  .defaultSystem(prompt)
  - 结构化输出：.entity(IReportPlan.class) / BeanOutputConverter
  - Tool Calling：Collector 的 ChatClient 注册 ReportDataTools
  - RAG：学习笔记切块入库（Redis Vector），Collector 的 searchNotes
  工具做语义检索
  - 审计 Advisor：全局加一个日志 Advisor，记录每个 Agent
